# pi-context-vault v0.1.0

Release date: 2026-08-14

## Guarantees

- A receipt replaces a tool result only after sanitized evidence has been durably written. If archival fails, the
  original model-visible result is preserved.
- Receipt retrieval is content-addressed, bounded, and protected from artifact-ID path traversal.
- Context reduction preserves chronological messages and valid tool-call/tool-result pairs; repository-map capsules
  are bounded, ephemeral, revisioned, and labeled as untrusted derived navigation data.
- Relevant filesystem changes are invalidated through a real chokidar watcher. Queries reconcile the dirty workspace
  and current Git HEAD before returning a map slice.
- Repository-map generations and state files are atomically activated. Concurrent runtimes serialize generation
  activation, and corrupt active metadata is rejected.
- A stale map is explicitly labeled and includes source/Git fallback evidence; it never silently claims freshness.
- State is isolated by canonical project path outside the project tree by default. Common credentials are redacted
  before hashing and persistence.

## Compatibility

- Node.js 22.19 or newer; CI acceptance covers Node 22.19 and Node 24.
- `@earendil-works/pi-coding-agent` 0.84.x.
- Linux receives the full CI suite. macOS and Windows receive package-install and real-filesystem-watcher smokes.
- Semantic maps support `.ts`, `.tsx`, `.js`, `.jsx`, `.mts`, `.cts`, `.mjs`, and `.cjs`; other text files use lexical
  indexing.

## Non-goals and known limits

- The extension does not guarantee the final provider payload size. Only Pi core can enforce that hard invariant at
  the final request boundary.
- v0.1.0 does not include embeddings, a complete cross-language call graph, typed long-term memory, automated Git
  checkpoints, or tool-episode subagents.
- Secret detection is heuristic and cannot prove that arbitrary sensitive content was identified.
- Repository maps are navigation indexes, not authoritative natural-language summaries or a substitute for source
  inspection and tests.

## Install

```bash
pi install git:github.com/Fubuyunhua/pi-context-vault@v0.1.0
```

The release issue closes only after this exact command succeeds against the pushed tag. Before the tag exists, CI
validates the same package manifest/content and Pi installation path against the release checkout.

## Upgrade path

This is the first public state schema (`schemaVersion: 1`), so no migration from an older release is required. Keep
`.pi/context-vault.json` limited to the documented keys. Derived repository-map generations may be safely rebuilt with
`/context-vault rebuild`; use `/context-vault gc` to apply the configured observation retention and quota.

Future releases that change persisted formats must either read schema 1 or publish an explicit migration. When
upgrading within v0.1.x, stop active Pi sessions first so the old watcher is closed, install the new immutable tag, and
run `/context-vault doctor` followed by `/context-vault rebuild` if the map reports stale.

## Post-release development note

Java AST indexing was implemented on `main` after this release. It is intentionally not listed as a v0.1.0
capability, and installing the immutable `v0.1.0` tag still provides lexical-only Java indexing. Use a development
checkout for Java evaluation until a newer immutable release is published.
