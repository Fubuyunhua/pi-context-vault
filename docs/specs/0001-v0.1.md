# Specification 0001: Context Vault v0.1

Status: Accepted for implementation

## Goal

Deliver an installable Pi package that reduces cumulative tool-output residency without making evicted evidence
irrecoverable, and that gives Pi a current, task-relevant map of TypeScript/JavaScript repositories.

## Normative guarantees

1. A tool result is never replaced by a receipt until its sanitized text is durably stored.
2. Every receipt carries a stable observation ID, content hash, size, tool identity, and evidence locator.
3. Context reduction preserves user messages and valid tool-call/tool-result structure.
4. Every model-visible repository-map slice includes its workspace revision and freshness status.
5. A stale or failed map update is reported and falls back to source-file, lexical, or Git evidence.
6. Generated state is isolated by canonical project path and stays outside the project tree by default.

## v0.1 surfaces

- Pi hooks: `session_start`, `session_shutdown`, `tool_result`, `context`, and `before_agent_start`.
- Tools: `context_vault_obs_get`, `context_vault_obs_search`, `context_vault_repo_map`, and
  `context_vault_status`.
- Command: `/context-vault status|rebuild|gc|doctor`.
- Optional project configuration: `.pi/context-vault.json`.

## Compatibility

- Node.js 22.19 or newer.
- `@earendil-works/pi-coding-agent` 0.84.x.
- Semantic repository maps for TS, TSX, JS, JSX, MTS, CTS, MJS, and CJS.
- Other text files receive filename and lexical indexing only.

## Non-goals

- A hard guarantee on the final serialized provider request size. Extensions do not own the final invariant boundary.
- LLM-generated observation summaries, embeddings, a complete call graph, typed long-term memory, automatic Git
  commits, or tool-episode subagents.
- Persisting unredacted secrets.

## Delivery slices

S00 bootstraps the package and CI. S01-S04 implement state and observation virtualization. S05-S07 implement the
repository map and runtime integration. S08 performs release hardening and Git-tag installation acceptance.

Each slice has one GitHub issue and one pull request. An issue closes only after its automated acceptance succeeds
and the corresponding PR is merged.
