# Specification 0001: Context Vault v0.1

Status: Accepted for implementation

Implementation status: v0.1.0 release candidate (2026-08-14)

## Goal

Deliver an installable Pi package that reduces cumulative tool-output residency without making evicted evidence
irrecoverable, and that gives Pi a current, task-relevant map of TypeScript/JavaScript repositories.

## Normative guarantees

1. A tool result is never replaced by a receipt until its sanitized text is durably stored.
2. Every receipt carries a stable observation ID, content hash, size, tool identity, and evidence locator.
3. Context reduction preserves user messages and valid tool-call/tool-result structure.
4. Every model-visible repository-map slice includes its workspace revision and freshness status.
5. A stale or failed map update is reported and falls back to source-file, lexical, or Git evidence.
6. Generated state is isolated by canonical project path and stays outside the project tree by default.

## v0.1 surfaces

- Pi hooks: `session_start`, `session_shutdown`, `tool_result`, `context`, and `before_agent_start`.
- Tools: `context_vault_obs_get`, `context_vault_obs_search`, `context_vault_repo_map`, and
  `context_vault_status`.
- Command: `/context-vault status|rebuild|gc|doctor`.
- Optional project configuration: `.pi/context-vault.json`.

## Compatibility

- Node.js 22.19 or newer.
- `@earendil-works/pi-coding-agent` 0.84.x.
- Semantic repository maps for TS, TSX, JS, JSX, MTS, CTS, MJS, and CJS.
- Other text files receive filename and lexical indexing only.

## Post-v0.1 development capability: Java semantic maps

Current `main` contains an additive, next-release Java AST index. This does not rewrite the immutable v0.1.0 tag or
claim that v0.1.0 includes Java. Snapshot `schemaVersion: 1` remains readable: Java adds optional `packageName`, import
flags, and symbol metadata fields, while all fields required by existing TS/JS consumers retain their shape.

The pure-Node `java-parser` CST extracts packages; normal/static/wildcard imports; class, interface, enum, record, and
annotation declarations; nested types; constructors, methods, fields, record components, and enum constants;
annotations, modifiers, generic parameters, signatures, source lines, and syntactic
`extends`/`implements`/`permits` evidence. It never invokes Maven, Gradle, `javac`, annotation processors, or project
code. It is a navigation index, not Java type solving, dependency resolution, method-body call-graph analysis, or
Lombok inference.

Malformed, oversized, or excessively nested Java input falls back to lexical terms with a bounded diagnostic. Such a
generation reports `unsupported` and does not claim fresh Java semantics. Per-file watcher updates, Git HEAD guards,
atomic generations, traversal rejection, no-follow symlink handling, and bounded query output apply unchanged.
Maven `target` and Gradle `.gradle` path segments are built-in exclusions.

## Repository-map consistency protocol

Every non-excluded filesystem `add`, `change`, or `unlink` invalidates the affected path. The runtime waits for the real
watcher to become ready, performs a queued fast update, reconciles all Git dirty paths, checks Git HEAD before every
query/context use, and atomically activates a complete generation under a cross-runtime file lock. The effective map
is the base snapshot for the observed HEAD plus the current dirty overlay.

The model receives a bounded task-relevant slice, never the full map. A slice is either revision-consistent and marked
`fresh`/`dirty`/`unsupported`, or is explicitly `stale` with source/Git fallback evidence. A corrupt pointer or
generation is rejected; it is never partially loaded as current map truth.

## Extension boundary

The extension's context transform is a best-effort, recoverable reduction layer. It estimates context conservatively,
but it does not see or own the final serialized provider request. Consequently, v0.1.0 does not claim the hard
invariant `effectiveInputTokens <= providerInputLimit`; that invariant requires enforcement in Pi core after all
extension transforms and immediately before provider sampling.

## Non-goals

- A hard guarantee on the final serialized provider request size. Extensions do not own the final invariant boundary.
- LLM-generated observation summaries, embeddings, a complete call graph, typed long-term memory, automatic Git
  commits, or tool-episode subagents.
- Persisting unredacted secrets.

## Delivery slices

S00 bootstraps the package and CI. S01-S04 implement state and observation virtualization. S05-S07 implement the
repository map and runtime integration. S08 performs release hardening and Git-tag installation acceptance.

Each slice has one GitHub issue and one pull request. An issue closes only after its automated acceptance succeeds
and the corresponding PR is merged.
